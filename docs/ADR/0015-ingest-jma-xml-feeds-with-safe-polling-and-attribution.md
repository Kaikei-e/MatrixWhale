# 0015: 気象庁防災情報XMLをPULL型アダプターで安全に収集し、出典表記と編集責任を明示して正規化する

## コンテキスト

MatrixWhale は日本国内の気象・地震災害情報を捕捉するため、気象庁（JMA）が公開する「気象庁防災情報XMLフォーマット」を取り込む必要がある。
気象庁公式情報（2026-09-21 調査確認）における前提条件と制約は以下の通りである。

- **配信方式**: PUSH型の提供環境は令和2年（2020年）9月1日に終了しており、現在はWeb上のPULL型のみ提供されている。
- **公式フィード**: `www.data.jma.go.jp` 配下で Atom 1.0 形式のフィード（高頻度: 毎分更新・約10分入電保持、長期: 毎時更新・数日間保持）が提供されている。
- **公表アクセス遮断基準**: 「気象庁防災情報XMLを公開しているURLに対し、1日10GB以上のダウンロードを伴うアクセスが確認された場合、アクセス元のIPアドレスを遮断する。遮断された場合、一度取得したファイルを再度取得しない等の改修をお願いする」と公表されている（1回重複で即BAN等の過剰規定はない）。遮断はアクセス元IP単位で執行される。
- **ライセンスと法的制約**:
  - コンテンツは「公共データ利用規約（第1.0版）」（CC BY 4.0互換）に準拠し商用利用可能。
  - 出典表記のほか、XMLを編集・加工して流通させる場合は「公開XML電文が独自に編集されていること、及びその編集責任が編集者にあること」の明示が義務付けられている。
  - 気象業務法第23条（警報の制限）により警報電文の本質を損なう改変は認められず、第17条（予報業務の許可）により独自予想の無許可発表は禁止されている。
- **品質・遅延**: PULL型の特性上、遅延や一時的欠測が生じる可能性があり上限時間は保証されない。緊急地震速報（EEW）のような即時用途には対応しておらず、無保証（No SLA）である。

## 決定

1. **Goアダプター `jma_adapter` の新設**:
   - `adapters/common` を活用した新規アダプターとして設計する。
   - デフォルト購読フィードは `JMA_FEEDS`（`eqvol.xml`, `extra.xml`）および `JMA_LONG_FEEDS`（`eqvol_l.xml`, `extra_l.xml`）の完全URL指定とする。
2. **保守的な自主アクセス予算とレート制限**:
   - 公表された10GB/日上限に対し、自主安全予算として1日最大1GiB（`JMA_DAILY_BYTE_LIMIT=1073741824`、公表値の約11%）を設定し、超過時は当日の電文フェッチを安全に抑止する（アダプター側で1GiBを超える設定を不許可）。
   - 高頻度フィードの巡回間隔は最短1分（`JMA_POLL_INTERVAL=1m`）、長期フィードは1時間（`JMA_LONG_POLL_INTERVAL=1h`）とする。
   - 個別電文の取得間隔には最低1.0秒（`JMA_REQUEST_INTERVAL=1s`）のスリープを挟み、単一電文長は最大8MiB（`JMA_MAX_ITEM_BYTES=8388608`）で制限する。
   - `If-Modified-Since` および `ETag` による条件付きGETを行い、サーバー指示の `Retry-After` を永続化して順守する。`User-Agent` には `JMA_CONTACT_EMAIL` を付与する（設定推奨、未設定も許容）。
3. **ステートのボリューム永続化と障害境界**:
   - 取得履歴ログ、未送信スプール（`spool/`）、HTTPキャッシュ検証値、当日消費バイト数を `JMA_STATE_DIR=/var/lib/jma` に fsync で保持し、Docker永続ボリュームを必須とする。
   - 重複取得防止は永続ステートに依存し、ボリューム消失や異常停止時には再取得が生じ得る境界条件を引き受ける。
4. **単一共有IPプロセスの遵守**:
   - IP単位遮断の影響がホスト全体に波及するのを防ぐため、同一グローバルIP環境下では `jma_adapter` を単一インスタンスで運用する。
5. **出典表記・編集責任・法規遵守の徹底**:
   - [[0004]] の `sea.source` に `jma` を登録し、出典および「本システムにて独自に編集・加工されており、編集責任は本システムにある」旨を属性・UIに明示する。
   - 警報データは本質を改変せず気象庁の発表を忠実に伝達し、独自予報は行わない。
   - 緊急地震速報（EEW）には非対応である旨を明記する。
6. **パーサー対応範囲とデータベース構成**:
   - パーサーは地震情報（`VXSE52` 震源に関する情報 / `VXSE53` 震源・震度に関する情報）およびH27方式市町村気象警報・注意報（`VPWW53`/`VPWW54`）を解釈・正規化する。
   - 警報境界ポリゴン化は未対応であり、地域コード・地域名を保持して `geom` は `null` とする（地震は有効座標時のみポイント正規化）。
   - 訓練・試験電文はアーカイブのみ行い実発報テーブルへの反映を抑止する。未対応電文（R06集約報・津波・火山等）は `sea.jma_message` に生XMLとして保持し、正規化は行わない。
   - DB側は `sea.jma_item`、`sea.jma_message`、`sea.jma_series`（発表時刻・取消ウォーターマーク）を管理し、端末エラー（HTTP 200パースエラー、400/404/410）は完了扱いで再試行ループを防止する。

## 根拠（調査結果・出典）

- **気象庁防災情報XML PULL型公開仕様**: [https://xml.kishou.go.jp/xmlpull.html](https://xml.kishou.go.jp/xmlpull.html)
  - 1日10GB以上のダウンロード超過時のIP遮断および重複取得防止の要請を明記。高頻度毎分・長期毎時の更新周期。
- **気象庁ホームページ利用規約**: [https://www.jma.go.jp/jma/kishou/info/coment.html](https://www.jma.go.jp/jma/kishou/info/coment.html)
  - 公共データ利用規約（第1.0版）準拠。商用利用可能、出典表記必須。ロゴ・キャラクター（はれるん）除外。
- **XML形式電文のご利用にあたっての留意事項**: [https://xml.kishou.go.jp/considerationforxml.pdf](https://xml.kishou.go.jp/considerationforxml.pdf)
  - 編集・流通時の編集責任明示義務（第3項(3)）、気象業務法第23条（警報の制限）および第17条（予報業務許可）の遵守。
- **気象データ高度利用ポータルサイト 留意事項**: [https://www.data.jma.go.jp/developer/ryuui.pdf](https://www.data.jma.go.jp/developer/ryuui.pdf)
  - SLA非保証、確実・迅速な配信が必要な場合の一般財団法人気象業務支援センター（JMBSC）利用案内。

## 検討した代替案

- **秒単位での超高頻度ポーリング**:
  - 不採用。公式フィードのサーバー更新周期は毎分（1分間隔）であり、秒単位でのリクエストは相手方サーバーへの過剰負荷となる上、情報取得の即時性は向上しない。
- **ステートレス運用（メモリ上のみでの重複管理）**:
  - 不採用。プロセス再起動やコンテナ再作成時にキャッシュが失われ、過去電文の再取得によって日次10GB上限や相手方サーバーの帯域を圧迫する重大なリスクがあるため、ボリューム永続化（`/var/lib/jma`）を採用した。
- **緊急地震速報（EEW）としての配信**:
  - 不採用。Web PULL型フィードには遅延が存在し、気象庁も免責・JMBSC利用を推奨しているため、EEW対応とは位置付けず、通常の地震情報・震度速報として取り扱う。

## 影響とトレードオフ

- **得るもの**:
  - 日本国内の公的気象警報・地震情報を、規約違反やアクセス遮断のリスクなく安定して継続取得できる。
  - 出典・編集責任の明示により、公共データ利用規約および気象業務法に対するコンプライアンスが担保される。
- **失うもの・引き受けるリスク**:
  - 秒単位のリアルタイム速報性は得られない（PULL遅延の受容）。
  - 現行パーサーの対象外（R06・津波・火山等）は生電文保管にとどまり、警報境界ポリゴンは `geom = null` となる。
