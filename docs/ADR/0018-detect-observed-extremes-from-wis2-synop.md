# 0018: WIS2 SYNOP観測電文から地上極値現象を検出し海況ハザードとして管理する

## コンテキスト

MatrixWhale は、NOAA NWS 警報、USGS / EMSC 地震、GDACS 複数災害、WMO Register of Alerting Authorities（RAA）に基づく各国 CAP 警報、および気象庁（JMA）防災情報 XML などを統合してきた。
さらに [[0016]] で WMO WIS2 Global Broker（MQTT v5）からの電文購読基盤を確立し、[[0017]] で pure-Go による BUFR Edition 3/4 デコーダーを導入した。

WIS2 の地上観測トピック（`cache/a/wis2/+/data/core/weather/surface-based-observations/synop/#`）からは、世界各国の地上気象観測局（SYNOP）から膨大な頻度とデータ量でリアルタイム観測値が配信されている。
しかし、このトラフィックの大半は平常時の気象データである。MatrixWhale は海況・防災監視プラットフォームであり、全世界の気象時系列を蓄積するアーカイブシステムではない。そのため、船舶の航行安全や沿岸の防災に直結する暴風、突風、豪雨、および猛烈な低気圧などの極値現象（extreme events）を選択的に抽出し、[[0009]] の多災害モデル（`sea.hazard`）へ統合することが求められる。

この極値検出およびデータパイプラインの設計にあたり、以下の前提条件・制約・満たすべき要件が存在する:

- **高トラフィックとバックプレッシャー制御**: SYNOP 電文は WIS2 の全トピック中で最大のトラフィック量を占める。MQTT 受信ハンドラーが決してブロッキングせず、過負荷時でもメモリ枯渇を起こさずに安全に超過データを制御できる機構が必要である。
- **責務分離の原則**: [[0002]] および [[0016]] で定めた通り、Go アダプターは電文の収集・パースに専念し、閾値判定・異常値判定・状態遷移などのビジネスロジックは Gleam / BEAM コアに一元化しなければならない。
- **データ品質と誤エンコード電文のリスク**: 実世界の観測網にはセンサー故障や通信ノイズが混入する。特に実際の運用電文の調査において、電文内の記述子オフセットが全体的にシフトしてエンコードされた不正電文（ecCodes でも同一に再現）が確認された。このような電文では、一部の要素がたまたま正常範囲内に収まっているように見えても他の要素が破損しており、見かけ上妥当に見える偽値（false values）が混入するリスクがある。
- **単独センサー異常と空間的裏付け（Corroboration）**: 自動気象観測局（AWS）の単独計器異常による偽陽性スパイクを排除するため、周辺観測局との空間的・時間的な裏付け検証が不可欠である。
- **地点カタログの依存性排除**: WMO OSCAR/Surface などの外部地点カタログへの同期ルックアップは、ネットワーク遅延や障害依存をもたらすため排除しなければならない。
- **エピソード管理と UI 統合**: 継続する荒天を単発観測の乱立ではなく「同一エピソード」としてマージし、既存の Hazards タブ、Timeline、リアルタイム SSE ストリーム、および地図レイヤーへ自然に統合する必要がある。

## 決定

1. **`wis2_adapter` による全 SYNOP サブセットのデコードと判定要素のバッチ転送**:
   - `wis2_adapter` はすべての SYNOP サブセット（WMO BUFR テンプレート `3 07 080`、`3 07 096`、`3 07 091`、WIGOS 識別子の有無を問わず、圧縮サブセット（compressed messages）を含む）を [[0017]] の pure-Go BUFR デコーダーでデコードする。
   - Go 側では閾値判定や極値判定を一切行わず、コア側での判定に必要な要素のみを抽出してバッチ（`POST /api/v1/wis2_data/observations`）で Gleam コアへ送信する:
     - 平均風速（mean wind: `wind_speed_ms`）
     - 瞬間最大風速およびその集計期間（gust with period: `gust_ms`, `gust_period_min`）
     - 降水量および各集計期間（precipitation with periods: 1時間、24時間等）
     - 海面更正気圧（MSLP: `mslp_pa`）
     - 観測位置（緯度 `lat`、経度 `lon`、標高 `elevation_m`）
     - 観測時刻（`observed_at`）
     - 地点識別子および地点名（`station_id`, `station_name`）
   - **非ブロッキング MQTT 受信ハンドラーとキュー制御**:
     - MQTT メッセージ受信ハンドラーは HTTP 送信や外部処理でブロックしてはならない。
     - バウンドされたインバウンドキュー（容量 1,000）と固定ワーカープール（16 並列）で非同期処理する。
     - コア送信用の観測値バッチキュー（上限 5,000 件）が満杯になった場合は、最も古い要素から破棄（drop-oldest）し、破棄カウンター（`wis2_observations_dropped_total`、`dropped_inbound` / `dropped_observations`）を Prometheus メトリクスに記録する。

2. **地点識別子（Station ID）の導出と外部カタログ非依存性**:
   - 地点識別子は WIGOS 識別子（`wigosSeries-wigosIssuer-wigosIssueNo-wigosLocal`）が存在する場合はそれを採用する。
   - WIGOS 識別子を持たない電文の場合は、伝統的気象官署ブロック番号（block）と局所番号（station）から `"0-20000-0-" + block + station`（例: `"0-20000-0-47662"`）の形式で合成・標準化する。
   - OSCAR/Surface などの外部地点カタログ（external station catalogue）は一切参照・照会しない。外部 API 呼び出しの遅延や障害点を完全に排除する。
   - 地点名（station name）は電文自体に含まれる場合（記述子 `0 01 015` または `0 01 019`）のみ保持し、含まれない場合は `null` とする（UI 上は `station_id` をフォールバック表示）。

3. **Gleam コアによる一元的な極値判定と環境変数による閾値設定**:
   - すべての判定（閾値判定・物理的妥当性・近隣検証・エピソード管理）は Gleam コア（`matrix_whale`）側で一元的に実施する。
   - デフォルトの判定閾値:
     - 平均風速（mean wind）: **20 m/s 以上**
     - 瞬間最大風速（gust）: **30 m/s 以上**
     - 1時間降水量（1h rain）: **50 mm 以上**
     - 24時間降水量（24h rain）: **150 mm 以上**
     - 海面更正気圧（MSLP）: **970 hPa 以下**
   - これらの閾値は環境変数によって個別に上書き（override）可能とする:
     - `WIS2_OBS_WIND_MS`
     - `WIS2_OBS_GUST_MS`
     - `WIS2_OBS_RAIN_1H_MM`
     - `WIS2_OBS_RAIN_24H_MM`
     - `WIS2_OBS_MSLP_HPA`
   - 気温極値（極端な高温・低温）は気候帯・地域・標高・季節に極めて強く依存し、グローバル一律の固定閾値による判定が困難かつ海況ハザードとしての即時性が低いため、本スコープでは対象外（out of scope）とする。

4. **厳格な物理的妥当性（Plausibility）検証と一括破棄ルール**:
   - 観測要素ごとに物理的限界値（physical limits）および期間妥当性（period sanity）を検証する:
     - 風速・突風: 0 〜 110 m/s
     - 突風集計期間: 1 〜 1440 分
     - 1時間降水量: 0 〜 400 mm
     - 24時間降水量: 0 〜 2000 mm（有効期間: 1, 2, 3, 6, 9, 12, 15, 18, 24 時間）
     - 海面更正気圧: 850 〜 1090 hPa
   - **観測電文の一括破棄（whole observation discarded）**:
     - 単一観測（サブセット）内の**いずれか 1 つの要素でも不合理・物理的限界外（implausible）である場合、その観測電文の全要素を破棄**する。
     - 実運用データにおいて、記述子オフセットが全体的にシフトしてエンコードされた不正電文（ecCodes でも同様に再現）が確認された。このような電文では、一部の要素がたまたま正常範囲内に見えても他要素が異常値を示しており、見かけ上妥当な値も偽値（false values）であるため、電文全体の完全破棄を必須とする。

5. **近隣観測局による検証（Corroboration）と表示制御**:
   - 閾値超過が検出された場合、直近 3 時間以内に当該局から **150 km 以内** にある別の観測局が、同一要素について **閾値の 70% 以上**（海面更正気圧の場合は **閾値 + 10 hPa 以下**、すなわち 980 hPa 以下）を観測・報告しているか検証する。
   - 条件を満たす近隣局が存在する場合、その超過は「確認済み（confirmed: `true`）」とする。
   - 近隣に裏付け観測が存在しない場合は「未確認（unconfirmed: `false`）」として登録する。
   - 近隣局探索のため、テーブル `sea.wis2_station` に各観測局の**最新 1 行のみ**を保持・更新する（履歴は持たない）。PostGIS 地理空間インデックス（`GIST(geom)` / `ST_DWithin`）により高速な 150 km 半径検索を行う。
   - UI 上の表現:
     - confirmed な極値は通常のハザード色（orange / severe）で明瞭に描画・強調する。
     - unconfirmed な極値は地図上およびリストで薄くフェード表示（faded display）し、単独異常値である可能性を利用者に視覚的に伝達する。

6. **エピソード（Episode）の結合管理・ライフサイクル・データ保管**:
   - 同一観測局かつ同一サブタイプ（`wind`, `gust`, `rain_1h`, `rain_24h`, `low_pressure`）の極値は、超過が継続する限り単一のエピソードとしてマージ・延長（merge / extend）する。
     - 最大値（気圧の場合は最小値）を更新し、観測回数（`episode_count`）を加算する。
     - 一度でも近隣局により confirmed と判定されたエピソードは、confirmed フラグが `true` に固定される。
   - **エピソードの終了**: 最後の閾値超過観測から **3 時間後** にエピソード終了（`is_current = false`）とする。
   - **データ格納**:
     - `sea.hazard` テーブルに `hazard_type = 'observed_extreme'` として保存する。
     - サブタイプ（`subtype`）および検証状態（`confirmed`）を保持する。
     - PostGIS のポイント座標（`Point`）および GeoJSON フィーチャーコレクション（`geometries`）を保持する。
   - **ストリーミングと UI 連携**:
     - リアルタイム SSE ストリーム（`/api/v1/hazards/stream` および共有ストリーム `/api/v1/stream`）に配信される。
     - Web UI の「Hazards」タブ（サブタイプ別フィルタ、未確認ハザードの非表示フィルタ機能付き）、地図上の海況チャートレイヤー、および時系列「Timeline」タブにシームレスに表示・更新される。
   - **データ保持期間（Retention）**:
     - エピソード終了（`modified_at` / `expires_at`）から **7 日後** にバッチで自動削除する（[[0009]] の GDACS ハザード retention と統一）。

## 根拠（調査結果・出典）

- **定性的・構造的事実**:
  - ※公開リポジトリの運用方針に基づき、自ホストの実測値やトラフィック件数などの定量的数値は含めず、構造的事実および仕様上の事実のみを記録する。
  - SYNOP 電文のトラフィック特性: WIS2 Global Broker において最も高頻度かつ大容量で流入する電文群であり、世界各地の観測局から数分〜毎時単位で到着する。Go の MQTT 受信ループで同期的な DB 書き込みや HTTP 通信を行うと即座にキュー詰まりやバッファオーバーフローを引き起こすため、バウンドされた非同期ワーカープールと drop-oldest ポリシーが不可欠である。
  - 不正電文の実例と再現性: 実運用電文の調査において、BUFR の要素オフセットが 1 項目ずれた状態でエンコードされた異常電文が発見された。この電文を ECMWF ecCodes に通したところ、全く同一のオフセットズレと異常値が再現された。この電文では特定のフィールドが物理的限界を逸脱していた一方、他のフィールドは偶然正常な風速や気圧の範囲内に収まっていた。もし一部の異常値のみを無視して正常範囲の要素を採用した場合、誤った偽の極値が発報されることになる。したがって「1要素でも異常であれば電文全体を破棄する」規則が実証的に必須である。
  - 近隣検証（Corroboration）の空間特性: 単独の自動気象観測局（AWS）では風車型風速計の機械的異常やセンサーノイズによる突発的スパイクが頻発する。一方、台風や爆弾低気圧、線状降水帯などの真の極値現象は数十〜数百kmの広がりを持つ。150 km 以内の近隣局による 70% 閾値での確認は、海洋・島嶼部などの観測所疎密地域でも有効に機能し、偽陽性を大幅に抑制する。
  - WIGOS ID vs 伝統的気象官署番号: 近代的な観測所は WMO WIGOS ID（シリーズ-発行者-発行番号-局所ID）を持つが、依然として多くの発展途上国や海洋観測所では 5 桁の WMO ブロック/局所番号（`0 01 001`, `0 01 002`）のみが送出される。両者を同一体系（`0-20000-0-BBSSS`）で正規化することで一意性を保証できる。

- **一次情報出典**:
  - WMO Manual on Codes (WMO-No. 306), Volume I.2: BUFR SYNOP テンプレート（`3 07 080`, `3 07 096`, `3 07 091` 等）
  - WMO WIGOS メタデータ標準 (WMO-No. 1192)
  - WMO Guide to Instruments and Methods of Observation (WMO-No. 8): 地上観測データの品質管理および物理的許容限界
  - ECMWF ecCodes: [https://confluence.ecmwf.int/display/ECC](https://confluence.ecmwf.int/display/ECC)

## 検討した代替案

- **Go 側での極値判定（judging in Go）**:
  - 不採用。Go のアダプター層に業務ロジックや閾値判定を持たせると、判定ルールの変更や環境変数による調整、エピソード結合ロジックが Go と Gleam に分散し二重管理となる。アダプターは純粋な収集・デコードに専念し、ビジネスロジックは Gleam コアに集約する（[[0002]]、[[0016]] の基本設計に従う）。
- **全観測データの時系列保存（storing all observations as time series）**:
  - 不採用。世界中の数万観測局から毎時・毎分届く膨大な通常観測データをすべて時系列データベースに永続化すると、ディスク容量の急激な枯渇、DB への書き込み I/O 飽和、インデックス肥大化を引き起こす。MatrixWhale の目的は海況・気象ハザードの監視であり、極値超過のみをエピソードとして記録し、観測局テーブルには最新 1 行のみを保持することでディスク・I/O コストを最小化する。
- **地図上に全観測局の最新値を常時表示（latest values for all stations on the map）**:
  - 不採用。地図上に世界中の膨大な観測点マーカーを常時描画すると、ブラウザの描画パフォーマンス（DOM/WebGL）が低下し、何より重要ハザードの視認性が著しく悪化する（UI clutter）。平常値は描画せず、警戒すべき極値エピソードのみをハザードレイヤーに表示する。
- **近隣局検証を行わず物理限界チェックのみで判定（only physical limits without corroboration）**:
  - 不採用。物理的限界値の範囲内であっても、風速計の機械的故障、落雷・電磁ノイズ、動物や異物の接触などによって「単独で 40 m/s の暴風」や「局所的な 0 mm / 1000 hPa 異常」といった偽陽性値（false positive）がしばしば発生する。空間的な裏付け（150 km 以内の 70% 閾値）なしにすべて警報扱いとすると、システムの信頼性が低下する。
- **閾値超過局同士のみでの近隣突合（neighbour check among exceeding stations only）**:
  - 不採用。過疎地や島嶼部、沿岸部など観測局が疎（sparse）な地域では、同一時刻に閾値（例: 20 m/s）を同時に超える観測局が 150 km 以内に複数存在する確率が著しく低く、真の猛烈な暴風であっても決して confirmed にならない問題が生じる。近隣局が閾値の 70%（例: 14 m/s）を記録していれば広域的な荒天として十分裏付けられるため、最新観測テーブル（`sea.wis2_station`）に対する 70% 基準を採用した。
- **OSCAR/Surface 等の外部局名カタログの参照（OSCAR/Surface names）**:
  - 不採用。WMO OSCAR/Surface 等の外部 API や巨大なマスターカタログをインジェスト時に同期参照することは、外部ネットワーク障害への依存、名前解決のレイテンシ、MQTT 高スループット処理の阻害要因となる。電文自体に含まれる局名のみを採用し、未記載の場合は ID を表示する方式とすることで完全な自律稼働と高信頼性を実現する。

## 影響とトレードオフ

- **得るもの**:
  - 世界中の地上・海洋気象観測網から、猛烈な暴風、突風、豪雨、異常低気圧などの海況・気象極値を準リアルタイムで自動捕捉・エピソード化できる。
  - 不正電文の一括破棄と 150 km 空間検証（corroboration）により、単独センサー異常による偽陽性を排除し、信頼性の高いハザード情報を届ける。
  - 最新観測局テーブル（1局1行）とエピソード化により、膨大な SYNOP トラフィックを最小限のストレージ・I/O 負荷で処理可能。
  - 既存の `sea.hazard`、Hazards タブ、Timeline、SSE 配信と完全に統合され、利用者は他ハザードと同等に極値現象を監視・フィルタできる。
- **失うもの・引き受けるリスク**:
  - 通常気象データの時系列グラフや過去気候統計の参照は行えない（目的外として割り切り）。
  - 150 km 以内に他の観測所が存在しない極端な孤立局（海洋上の孤立島や極地など）では、真の極値であっても unconfirmed（薄表示）にとどまる。
  - 1要素でも物理的限界を逸脱した場合に電文全体を破棄するため、一部に有効なデータが含まれていた場合でも同時に失われる（偽極値の混入防止を最優先）。
  - 気温の極値（熱波・寒波）は本パイプラインの対象外であり、別途気候・地域適応型の判定モデルが必要。
